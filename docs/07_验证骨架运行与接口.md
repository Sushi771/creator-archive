## 现有 Edge HAR 分页证据（实验）

用户已选择只用现有Edge，不启动独立浏览器、不复制Cookie或profile。当前Edge控制工具不提供网络响应体；本入口处理用户正常导出的HAR，**不是自动采集服务**。参考[微软Edge官方导出说明](https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/reference#save-all-network-requests-to-a-har-file)。

### 最短操作

1. 在现有Edge打开两位既有样本中的任一作者主页，按F12，选“网络 / Network”。先开启网络面板再刷新主页，使记录包含初始空游标；本次只访问该作者，不切到聊天或账号管理页。
2. 在网页中正常向下滚动几次，网络列表可筛选 `user_posted` 观察请求。出现登录、验证或限流提示时停止，保留已加载部分；“没有新卡片”不等于末页。
3. 点击网络工具栏“导出HAR（已清理） / Export HAR (sanitized)”，另存为 `XHS-A-part1.har` 或 `XHS-B-part1.har` 到 `%LOCALAPPDATA%/CreatorArchive/private-validation/G1-2026-09-26/har-inbox/`。首次先导出有限记录核验字段，无需一次滚完整个历史。该工具栏可能导出未筛选的全部请求；解析器只处理白名单作者分页。**不要开启包含敏感数据的导出**。已清理HAR仍可能含正文/URL参数，因此只留此本机目录，不上传聊天或Git。
4. 告知Codex文件名即可继续验证；也可把HAR文件拖到仓库根目录 `verify-xhs-har.cmd` 自动导入。启动器使用已有 `.venv`，不会安装依赖；导入完成后按任意键关闭，运行中按Ctrl+C停止。终端显示样本代号、页数、去重数、停止原因及下一步。

默认结果在同一私有根目录的 `xhs-har-validation/`：`capture-index.json` 只保留白名单字段及来源文件SHA-256，`archive.sqlite3` 为独立验证库，`report.json` 为脱敏计数/错误及下一步。原始HAR不被复制，原samples、媒体和WeWe库不被修改。一次只运行一个导入进程。

### 分页与恢复核验

CLI可控制首次只提交两页，然后在另一进程继续。以下命令从当前 `codex/dual-platform-integration` 工作目录运行；无需再安装Python依赖：

```powershell
.venv/Scripts/python.exe -X utf8 -m scripts.verify_xhs_har --har "$env:LOCALAPPDATA/CreatorArchive/private-validation/G1-2026-09-26/har-inbox/XHS-A-part1.har" --max-pages 2
.venv/Scripts/python.exe -X utf8 -m scripts.verify_xhs_har --har "$env:LOCALAPPDATA/CreatorArchive/private-validation/G1-2026-09-26/har-inbox/XHS-A-part1.har"
```

补录后把新的HAR拖到同一启动器，或将路径换成新文件，默认复用原批次与成功页；不用从零重做。缺页保留下一游标，错误页不推进；只有捕获API明确 `has_more=false` 才能完成捕获链。初始空响应、未知身份、循环或不同成功响应共用同一游标均不会被当作成功。对冲突保留旧状态，先核查是否混合了不同时段的扫描；需单独扫描时可用 `--root` 指向LOCALAPPDATA内一个全新目录，不删除旧结果。

该实验当前只接受已核对形状：HTTPS官方域名、GET `/api/sns/web/v1/user_posted`、唯一 `user_id/cursor`、24位小写十六进制ID/游标、HTTP200、`success=true/code=0`、布尔 `has_more`；不匹配就保留缺口，待真实响应核对后最小调整。HAR上限128MiB，缺响应体会明确报未完成。HAR属于用户提供且可编辑的本机证据，不能单凭文件来源字段宣称工具直接见证请求；返回 `user_supplied_capture_replay`、`live_transport_resume_verified=false`、`g1_passed=false`。

即使捕获链四页/末页和新进程导入均通过，**仍不证明自动采集器从持久游标发出新的认证请求并恢复**，也不证明全量正文/媒体、订阅生命周期或双平台G1。公众号无后台权限和工具站点拒绝仍是独立阻塞。

## HTTP 接口（仅实验，不是最终产品 API）

| 路由 | 行为 |
| --- | --- |
| GET `/api/status` | 版本、validation_only、g1_passed=false、两平台尚未接入的能力、模拟检查点 |
| POST `/api/links/classify` | `{text}` → 平台、链接类型、候选 ID、identity_verified=false、can_subscribe=false；错误422 |
| POST `/api/demo/run` | `{inject_failures: true/false}` → 固定四位模拟作者的逐源结果；运行中返回409；不会访问平台 |

POST 要求 `X-Creator-Archive: local-validation`，有 Origin 时须与本服务一致；不开放跨域。Host 只接受本机主机名（`testserver` 仅供测试）；绑定回环、无访问 URL 日志、CSP 禁止外部脚本和嵌入。这个请求头是跨站操作防护，不是生产身份认证。本版只存模拟数据；接入真实资料前须补配置目录与认证。

## 持久化合同

- Store 创建独立 SQLite 连接并确定性关闭。平台/作者是运行唯一键，平台/作品是内容唯一键。
- 一页的作品与下一游标、请求游标、ID 集合、末页依据、观察时间在同一事务提交，随后才请求下一页。进程在提交后退出可从下一游标恢复。
- 检查页级身份和已有作品归属；发现冲突整页回滚，不能把作品移动到另一个作者。
- has_more 必须为布尔值；完整必须有明确末页证据且无下一游标。空页但仍有下一页、缺游标、循环游标、上限、错误均不能标完成。
- 401 类错误要求明确恢复；429 类错误的冷却时间持久化；超时保留失败页。适配器版本改变阻止盲用旧游标；意外异常只存固定类别，避免把敏感响应写入公开结果。
- 当前是串行的有限验证器：页数预算默认100，到上限为 partial，可继续；没有生产任务租约、取消、自动退避调度、真正 full/latest 多运行历史或游标失效重扫。不能直接接真实采集器便称完整任务系统。

## 统一工作流实验入口（仅自造数据）

在仓库根目录执行：

```powershell
.venv/Scripts/python.exe -m scripts.demo_workflow --max-pages 2
.venv/Scripts/python.exe -m scripts.demo_workflow --batch-id 1 --mode archive
```

第一条建立两平台各两位模拟作者（含暂停订阅），每位扫描两页后保存为 partial；第二条在新进程从页游标继续到明确末页。终端输出逐作者页数、唯一作品数和状态。按 `Ctrl+C` 停止运行中的命令；再次使用同一批次 ID 即可继续。默认结果在 `data/validation/workflow-demo/archive/平台/稳定作者ID/`，状态库在同级 `archive.sqlite3`，均被 Git 排除。可用 `--root` 指定其他实验目录；勿指向已有真实资料目录。该入口不访问平台，也不生成真实正文或媒体。

工作流接口由平台适配器提供已核验身份和 `page(author_id,cursor)`；`full`、`latest`、`archive` 分开建立批次。当前没有可证明安全的“最新水位提前停止”规则，所以 `latest` 仍遍历可获取页并单独记录结果。每页 ID 和游标同一事务提交，重新运行同一批次只继续缺失页；一个作者或平台失败不会阻断其他作者。详情来源 URL 只保留官方域名和必要文章身份参数，小红书分享会话参数不写入语料。手工修改的生成文件不会被覆盖，新版会写带内容哈希的文件名。媒体只接受已下载的本地文件，流式复制并做签名、大小和 SHA-256 校验；清单标 `media_coverage=unknown_expected_count`，不能据此宣称全部附件已离线或可解码。旧验证库与既有用户目录均不迁移或改写。
