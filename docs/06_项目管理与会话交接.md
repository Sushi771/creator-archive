# 项目管理与会话交接

版本：v0.2.5｜2026-09-26

## 管理方式

Codex 本地项目 **Creator Archive｜公众号与小红书博主归档** 已创建，主文件夹是 Git 仓库 `C:\Users\ss\OneDrive\Desktop\creator-archive`。现有同主题 ChatGPT 项目可以继续承接讨论；Codex 本地项目用于直接读取仓库、执行 Git 和发现根目录的 AGENTS.md。本次最初的任务仍位于项目外的临时目录；后续从该 Codex 项目新开任务即可，无需搬入整个旧聊天。

不要将一个无限延长的任务当作唯一项目记录，也不要只把旧文档包放入项目后长期不更新。项目能集中材料，但不能替代每次开始时读取最新仓库、明确任务范围和完成后交接。

## Codex 的项目说明放在哪里

此前建议在 Codex 项目界面粘贴 Instructions，混淆了 ChatGPT 项目与 Codex 本地项目。当前 Codex 开发任务使用仓库根目录的 AGENTS.md 作为持久规则；该文件已写明双平台 P0、文档与状态同步、敏感信息排除、验证口径和开发阶段边界，无需在项目界面另找输入框。PROJECT_STATUS.md 记录当前阶段与下一步，CHANGELOG.md 记录每次实际改动。今后需要调整规则时，修改 AGENTS.md，并同步状态和日志。

参考：[Codex 项目与本地文件夹](https://learn.chatgpt.com/docs/projects)、[AGENTS.md 项目指导](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

## 模型与思考档位

- 首个双平台 G1 技术验证、组件取舍和架构决策：`gpt-6-astra`，`high`。遇到特别复杂的证据冲突或关键设计难题，再单次提升为 `xhigh`。
- 后续范围清楚的模块实现：`gpt-6-sol`，`medium`；跨模块重构、疑难恢复逻辑或严格审查用 `high`。
- 轻量文档整理或单一小改动：`gpt-6-luna`，`medium`。模型按每个新任务单独选择，不将模型名写死为仓库规则。

选择依据见 [OpenAI 模型选择说明](https://learn.chatgpt.com/docs/model-selection)。更高思考档位会增加耗时和用量，先按任务复杂度选择。

## 会话划分

同一 Codex 项目下，每个任务处理一个可验收目标，例如“文档评审”“公众号全历史技术验证”“小红书作者分页验证”“归档格式与离线阅读”“订阅任务与恢复”“产品界面”“发布验收”。总控任务处理需求变更、优先级与跨模块决定；模块任务只携带所需文档，避免无关上下文反复累积。

文档评审、技术验证、经用户确认后的应用开发是明确的交接边界；完成一个模块或一次验收后也应开新任务。若当前任务已跨多个模块、反复重述已记录的决定，或长上下文使进度难以准确复述，先结束当前可交付单元并更新状态，再开新任务。不按固定消息数机械切换，不把未记录的中间状态留在旧窗口。

每个任务的最终交付都应明确告诉用户现在继续当前任务还是在同一项目开新任务，并说明具体理由；建议切换时给出下一任务标题、目标和可复制启动句。若长任务中途出现上下文风险，应提前提醒，先完成可行的当前工作与交接记录，再切换。

两个会话并行开发时，应使用独立分支/worktree或明确互不重叠的文件范围；不得同时推送同一分支。接口和统一数据模型变化须先协调，不能各自引入不兼容字段。只读调研可以并行。

## 每次开始与结束

开始：核对远端最新分支/commit → 阅读最小入口 → 明确当前任务、修改范围、验收条件和已有阻塞。对当前资料已有答案的事项不重复问用户。

结束：记录已完成、未完成、验证、下一步 → 同步相关文档与状态 → 自动提交并推送（用户已预先授权，无需再次确认）→ 核对远端 → 给用户提交链接和简短结果。交接记录须包含分支与 commit、改动文件、验证结果、阻塞和下一个可验收目标。若推送失败，明确尚未同步，不将本地状态当成远端状态。

重大取舍在 docs/ 下建立 ADR：问题、候选、证据、决定、影响和可撤销条件。开始实现后可把可独立验收任务列为 GitHub Issue，关联需求编号与PR；无需先引入复杂管理工具。

## 新会话启动句

“继续 Creator Archive（同一 Codex 本地项目）。当前阶段：【文档评审/技术验证/开发】；基线：【分支与 commit】。先核对远端最新状态，再读 AGENTS.md、PROJECT_STATUS.md、CHANGELOG.md 最近条目和【相关文档】。本次目标：【单一可验收结果】；修改范围：【文件/模块】；验收：【具体检查】。上一任务完成：【提交链接】；未完成或阻塞：【事项】。用户已于2026-09-26授权开发；真实G1通过前不得宣称完整订阅能力已通过。结束时同步相关文档、状态与日志，提交并核对远端。”

无需把旧聊天全文复制过来。遇到记录缺失先查看对应提交、需求和研究证据，确实影响实现时再向用户确认。
