# ADR-001：G1 未实测时的实现边界

状态：接受验证骨架；正式平台方案待定。日期：2026-09-26。

## 问题与候选

用户已授权开发，但两平台真实账号和多页样本尚缺。候选一是直接整包接入现有采集器；这会把首屏、空页或页数上限误当作完整历史，且尚未完成实际账号与许可适用性确认。候选二是先建立可替换协议和离线验证骨架，再用相同合同验收真实组件。选择候选二。

## 决定

- 沿用 docs/03 拟议的 Python/FastAPI + SQLite；当前机器 Python 3.14.0，锁定本轮实际测试依赖。HTTP 服务只监听回环。
- 骨架展示两平台能力状态、链接分类与模拟扫描；真实作者反查、正文/媒体采集未实现时返回明确的能力缺口，不能创建假订阅或假完成状态。
- 自有验证引擎以平台/作者/作品稳定 ID、逐页事务和持久游标演练恢复。历史完成与正文/媒体状态分开；只有显式可靠终止证据可完成。
- 四个采集组件仅做固定源码审阅，不安装、不复制源码、不自动启用写平台工具。正式选择仍以真实 G1 为门槛。

## 影响与撤销条件

可以先验证通用可靠性并提供可运行入口；代价是骨架尚不能下载真实博主内容。模拟不证明平台游标或登录寿命。获得真实样本与账号后补做 G1，更新 ADR 与组件登记，再增加正式适配器。不是把全作者订阅降级为单篇下载，也不是改变 R01–R13。

## 本轮落地

验证环境 Python 3.14.0 / SQLite 3.50.4 / FastAPI 0.141.1 / Uvicorn 0.54.0，全部直接间接依赖见根目录 requirements.lock；版本与许可文件哈希见 validation/runtime-dependencies.json。选择标准库 unittest，httpx只用于API测试。采用原生HTML/CSS/JS，验证台无复杂组件状态，暂不引入前端构建框架；正式界面在真实适配器与产品流程稳定后决定。21项离线测试与本机浏览器操作通过，正式采集组件仍未采用。

## v0.3.5真实探针结果

已取得双平台样本入口、已有Edge会话及WeWe本机目录。XHS身份与媒体文件探针取得真实证据；其四页响应、末页和作者分页进程恢复未通过，公众号受工具站点策略阻塞。允许保留本轮局部真实证据，但仍不接受正式平台选型，也不将Edge/HTTP探针成功算到未执行的第三方组件API。现有WeWe仅启动本机界面，未运行采集；不再将“四组件仅静态”误解为本轮没有启动过用户已有应用。详见 [真实G1记录](validation/G1-live-2026-09-26.md)。
