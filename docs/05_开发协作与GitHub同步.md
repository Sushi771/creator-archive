# 开发协作与 GitHub 同步约定

> 当前阶段：开发前文档评审；首次文档基线接续用户的 Initial commit。远端同步结果以 `main` 和文件核对为准。

版本：v0.2.3｜2026-09-26｜状态：文档阶段，首次仓库基线

## 仓库决策与本轮状态

用户已创建并指定 [Sushi771/creator-archive](https://github.com/Sushi771/creator-archive)，默认分支 `main`，创建时可见性为公开；本次未更改可见性。旧 `wewe-rss-ss` 保持为已有应用及参考来源。主仓库保存本产品文档、实现、测试、依赖决策和脱敏验证记录，不上传博主正文、媒体或账号数据。

本次资料接续用户的 Initial commit，建立首次文档基线，包含 README、AGENTS.md、忽略规则、六份设计文档、三个研究附录、CHANGELOG、PROJECT_STATUS、项目管理说明和提交评审模板。当前没有应用代码，也没有真实平台运行验证。后续以本仓库为开发资料的权威来源，历史下载文档包为当时快照。

首次同步时，旧 ChatGPT GitHub 连接的 Git 对象写入仍返回 403，本机 Git HTTPS 到 `github.com:443` 也遇到网络超时或重置。经本机 Git Credential Manager 中已授权的 `Sushi771` 账号，使用 `api.github.com` 的 Git Data API 发布与本地完全相同的 tree 和 commit，并以非强制快进更新 `main`；远端分支、文件路径与 blob 哈希已核对。后续常规 Git 操作仍应先检查 Git HTTPS 连通性，不把旧连接视为已获写入授权。

同步必须完成远端写入并核对分支 SHA 和文件内容才可向用户报告成功；不能以本地 commit 或下载包冒充远端同步。不强推、不覆盖他人更新，不索取个人访问令牌。

## “实时同步”的执行定义

开发过程中，每完成一个可核验的小工作单元就提交并推送。每次更新都必须同步受影响文档、CHANGELOG.md 和 PROJECT_STATUS.md，文档/接口变化与相应实现同一批提交。开始工作先核对远端，结束一个阶段记录 commit SHA、分支、变更、验证结果和剩余事项。不等项目全部完成才第一次上传。

它不是逐按键上传，也不是本轮结束后仍有后台代理持续运行。若网络/权限导致失败，保留本地工作并明确“尚未同步”，恢复后先比较远端再推送；不得覆盖他人更新或强推隐藏冲突。

每条提交备注至少写明：为何修改、修改内容、同步文档、已做验证、未完成或受限事项。纯实现细节未改变需求时，也要在更新日志说明“需求和接口不变”及验证结论。验证未执行写明原因，不以“已测试”笼统替代证据。当前提交的 SHA 由 Git 自身记录；更新日志以日期/版本和提交标题对应，避免在同一提交中自引用尚未生成的 SHA。

建议 `main` 保持可审阅基线，功能使用 `feat/...`、修复使用 `fix/...`、文档使用 `docs/...`；按任务提交并创建PR。仓库公开不等于已选择开源许可证；分发许可、分支保护和后续可见性调整另按用户用途决定，当前不额外更改账户权限。

## 多 agent 的具体分工

本轮已实际并行使用三个agent：`wechat_reuse` 核查公众号；`xhs_reuse` 核查小红书；`douyin_reuse` 核查抖音/多平台。主agent负责统一需求、核对冲突、写文档和保存。各研究均有固定源码版本和明确未实测声明。

后续在用户授权的并行范围内，按互不重叠文件/模块分工：平台适配、归档/语料、界面、验证。每项任务先分配写入目录、接口和验收标准；主agent整合接口与提交，避免多个agent同时更改同一文件或推同一分支。可用独立worktree/分支隔离实现；只读调研可以并行。

代理报告必须区分“源码存在”“测试通过”“真实平台通过”。发现阻塞要报告原因，不能通过降低P0范围宣称完成。相互评审重点是覆盖、媒体状态、恢复和许可，不靠堆叠重复测试。

## skills 使用规则

本轮使用文件管理 skill 更新原有文档并保留版本；使用插件管理 skill 核查连接能力；平台研究由对应 agents 执行。本轮没有安装不明第三方 skill，也未运行第三方采集项目。

后续按实际任务调用 GitHub、文档、浏览器验证、视频处理等已提供的相关技能；无合适技能时先检索官方文档或 GitHub，审阅来源、权限、安装脚本与许可证后再决定。skill负责操作流程，平台项目负责业务组件，不能用一个提示词文件代替不存在的作者分页接口。

## 提交与审阅清单

- 需求编号、接口、目录格式变更必须更新对应文档；记录为何需要以及对用户行为的影响。
- 复用依赖先记录 commit、许可、采用方式、差距和真实验证证据；不将受限源码直接复制进仓库。
- 测试针对具体风险：跨页覆盖、置顶去重、中断恢复、部分失败、离线附件与路径安全；简单文档改动只做一致性和链接检查。
- 提交前查看 staged diff 和文件清单，防止 secrets、Cookie、含签名URL、数据库、媒体、原始日志误入Git；.gitignore不能替代检查。
- 同步后确认远端分支/commit确实存在，报告可访问的仓库/提交链接；不能仅凭命令启动或本地提交判断成功。

## 不纳入仓库的资料

`.env`、token/cookie、浏览器profile、会话缓存、证书和密钥、SQLite与日志、Obsidian Vault、archive/downloads/media/corpus等真实内容、模型缓存及临时输出。测试只提交自造或有明确再分发权限的小样本与脱敏错误分类。无论公开或私有仓库均执行同样规则。
