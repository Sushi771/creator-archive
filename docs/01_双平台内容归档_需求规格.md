# 博主订阅与内容归档｜需求规格

版本：v0.2.2 已确认需求基线（2026-09-26授权开发，需求不变）｜2026-09-26

## 产品目标与修订

用户提供公众号文章/主页或小红书笔记/主页链接，应用识别所属博主，建立应用内部订阅。用户可手动更新全部订阅博主的全部可获取历史内容，并一键按博主分目录下载正文、图片、可获取视频和离线阅读文件，供 AI 分类、总结和分析文风。ChatGPT 可读取归档和已授权的采集结果。抖音纳入架构和复用调研，首版交付边界仍为公众号和小红书。

本版废止 v0.1 中“小红书账号级批量抓取不进首版”“公众号历史导入为后续扩展”的安排。两平台的作者识别、订阅、历史分页和批量归档均为 P0。单篇保存只作为补充入口，不能替代订阅能力。

## 三种操作的准确含义

| 操作 | 处理对象 | 完成标准 |
| --- | --- | --- |
| 订阅博主 | 从链接解析出的平台与稳定作者 ID | 显示作者供用户确认，建立本应用订阅；不自动关注平台账号；同名异人分开 |
| 更新全部内容 | 全部订阅博主；可单选或多选缩小范围 | 对各博主扫描全部当前可获取历史，更新内容索引和已改变的资料、恢复未完成分页；不是只拉首页或最新十篇 |
| 按博主下载全部 | 全部订阅或所选博主的全部可获取内容 | 如历史扫描未完成则先扫描再下载；补齐正文与媒体，按博主出清单；不受当前页面、搜索筛选或缓存篇数限制 |

“全部订阅”包含暂停的订阅：暂停仅阻止自动调度，用户明确点击全量手动更新或下载时，按按钮展示的全部范围执行，不改变订阅的暂停设置。单次运行中的任务另有暂停/继续操作，二者不能混淆。

另提供“检查最新”快捷操作用于后续增量更新。它必须与“更新全部内容”区分，不能静默把全量改成增量。

“全部可获取”指在本次账号权限、平台接口和访问条件下，经有效分页遍历能够获得的范围。必须记录最早/最晚作品日期、遍历页数、实际数、未完成原因和覆盖状态；不得承诺包含已删除、私密、已隐藏或平台未返回的内容。平台总数只作为参考，不代替逐页完成证据。

## 首版功能与验收

| 编号 | 优先级 | 需求 | 可验证的标准 |
| --- | --- | --- | --- |
| R01 | P0 | 公众号/小红书作品与作者链接识别 | 作品链接先确定平台作者 ID，再展示作者名、头像和主页；不可推断时要求补充主页链接；支持分享文本含链接 |
| R02 | P0 | 两平台统一博主订阅 | 添加、取消订阅、暂停、恢复、标签；作者改名不新建第二个作者；取消订阅默认保留归档 |
| R03 | P0 | 全量历史遍历 | 每平台至少一个跨3页的作者样本，不因遇到置顶、重复、空页或数量上限而错误宣称已完成；限流暂停后可续传 |
| R04 | P0 | 更新全部内容 | 所有订阅按队列执行全量扫描，逐博主显示结果；失败一人不丢失其他结果；重复点击复用任务，避免重复采集 |
| R05 | P0 | 检查最新与内容去重 | 按平台作品 ID 去重，识别新作及可检测的编辑；置顶内容不造成漏采；删除或不可见只标记，不删除历史副本 |
| R06 | P0 | 分博主一键下载全部 | 一次操作覆盖全部订阅，按稳定作者 ID 分文件夹；待下载、完整、部分、失败分别计数；下载范围与扫描快照绑定 |
| R07 | P0 | 图文与视频保存 | 正文、图片顺序、可取得的视频文件、封面与来源保存；平台返回最高可访问画质的原字节，不承诺作者上传原件；缺资源明示 |
| R08 | P0 | 排版与 Obsidian | 正文 Markdown + 离线 HTML + 本地附件；跨目录移动及断网阅读可用；结构、标题、列表、表格、图片顺序验收；HTML尽量保留样式，Markdown不保证像素相同 |
| R09 | P0 | 可供 AI 使用的作者语料 | 每博主有索引、manifest.json、corpus.jsonl；有全库索引；保留作者ID、作品ID、来源、时间、正文、媒体状态及内容哈希；不混入失败占位文案 |
| R10 | P0 | 持久化队列与失败恢复 | 程序重启后恢复游标和资产状态；401需重新登录，429冷却，超时有限退避；仅重试失败页/资源，不重下所有成功文件 |
| R11 | P0 | ChatGPT按作者读取 | 提供作者列表、某作者作品列表、作品正文/图片、语料分页；清楚返回总数/本次覆盖/是否截断，能定位原文 |
| R12 | P0 | 搜索、目录与本地安装 | Windows 本地安装/启动；按平台、作者、日期、文字、归档状态检索；配置归档根目录及Obsidian目录；卸载不删除资料 |
| R13 | P0 | GitHub同步开发资料 | 文档、依赖决策、测试记录及代码按可复核工作批次提交推送，记录commit；不上传采集正文、媒体、账号凭据及真实日志 |
| R14 | P1 | 视频转写、关键帧、图片OCR | 衍生内容带时间戳和来源；原文件保存与理解分开计状态；在无这些结果时不得称已分析整个视频 |
| R15 | P1 | 自动定时更新及抖音适配 | 复用同一作者订阅、分页、归档接口；电脑与后台在线时运行。定时不是首版手动功能的替代 |

## 语料用途与边界

首版负责把素材整理到 AI 能读取的形式，支持按作者选择语料用于分类、总结、文风分析和示例学习。不会因下载自动上传整个资料库、调用收费模型或启动微调训练。若后续需要真正训练模型，再明确所用内容的授权、训练格式、预算和排除项。正文与转写/OCR/AI产物分字段保留，方便选择。

## 质量与状态

作者扫描覆盖状态与下载状态分开：历史已遍历不代表媒体都已下载；媒体完整也不代表作者历史已遍历。作者扫描状态：未扫描/扫描中/已遍历当前可见范围/受限/中断/能力不支持；作品归档：完整/部分/失败。批任务必须满足“总数=已完成+部分+失败+待处理+取消”，并允许未知历史总数显示为未知。

禁止：把最新一篇当全部、把第一页当全部、把封面当视频、把远程图片URL当离线文件、把下载错误文案放进训练语料、为解限流轮换账号/IP、覆盖用户Obsidian手工笔记。

## 验收样本与门槛

两平台各至少2名博主，其中至少1名有3页以上历史；涵盖图文、视频、置顶、同名作者、同标题不同作品。加入公众号普通嵌入视频与视频号卡片，后者若只能保存卡片须明确标记。测全部订阅一次下载、重启续传、第二次更新、部分失败、同作者改名和离线移动目录。

原用户样本用于单链解析：公众号短链 6BIQ5H7DE1LR3i7eaSEt0g；小红书作品ID 69846d1f000000001a022f48，测试时重新获取有效分享参数。它们不能独自证明作者全量能力。真实平台抓取未完成前只能标“源码/文档支持、待实测”。
